# 차일디 목표관리 시스템

## 프로젝트 개요

차일디 목표관리 시스템은 팀 구성원들의 OKR(Objectives and Key Results)을 설정하고, 진척률을 관리하며, 승인 프로세스를 처리하는 웹 기반 성과 관리 시스템입니다.

## 주요 기능

### 1. 대시보드
- 구성원별 OKR 달성 현황 조회
- 월별/분기별/연간 단위 조회 지원
- Key Results별 진척률 시각화

### 2. 목표 설정 및 합의
- 새로운 OKR 작성 및 등록
- Key Results 추가/삭제 기능
- 승인 요청 및 취소 기능
- 상태별 관리 (작성중, 승인 대기중, 합의 완료)

### 3. 내 목표 관리
- 합의 완료된 OKR 조회 및 수정
- Key Results 진척률 업데이트
- 수정 승인 요청 (OKR 변경, KR 내용 변경, KR 항목 증감, 진척률 보고)
- 실시간 변경사항 추적

### 4. 요청 관리 (관리자 전용)
- 모든 승인 대기 요청 조회
- 요청 유형별 필터링 (신규 수립, OKR 변경, KR 변경, 진척률 보고)
- 변경 전후 비교 상세 보기
- 승인/취소 처리

### 5. 회원가입 승인 시스템
- **회원가입**: 신규 구성원이 가입 신청 시 `is_approved: false` 상태로 생성됨
- **로그인 차단**: 미승인 상태(`is_approved: false`)에서 로그인 시도 시 "승인 대기중입니다." 알럿 표시
- **승인 권한**: 대표, 본부장, pms1(박명수)만 가입 승인 가능
- **승인 경로**: 구성원 메뉴 > 상단 `가입 대기자 (n)` 버튼 > 대기자 목록에서 승인/거부
- **승인 처리**: 승인 시 `is_approved: true`, `is_hidden: false`로 업데이트 → 즉시 로그인 및 모든 화면에 표시
- **거부 처리**: 해당 구성원 데이터 삭제 (복구 불가)
- **Baserow 필드**: `members` 테이블의 `is_approved` (Boolean, 기본값 true), `is_hidden` (Boolean, 기본값 true)
  - 기존 구성원: `is_approved: true`, `is_hidden: false`
  - 신규 가입자: `is_approved: false`, `is_hidden: false`로 생성

## 주요 기능 흐름

### 1. OKR 신규 수립
1. 사용자가 "목표 설정 및 합의" 화면에서 OKR 작성
2. Key Results 추가 및 내용 입력
3. "승인 요청" 버튼 클릭
4. 관리자가 "요청 관리"에서 승인
5. 상태가 "합의 완료"로 변경

### 2. 진척률 업데이트
1. 사용자가 "내 목표 관리"에서 진척률 조정
2. "수정 요청" 버튼 클릭 및 코멘트 작성
3. 관리자가 "요청 관리"에서 변경사항 확인
4. 승인 시 실제 데이터에 반영

### 3. OKR/KR 수정
1. 사용자가 "내 목표 관리"에서 OKR 또는 KR 내용 수정
2. 시스템이 자동으로 변경 유형 감지
3. 수정 요청 제출
4. 관리자 승인 후 반영

## AI 피드백 리포트 생성 가이드

### 개요
`feedback/` 폴더에 AI가 생성한 구성원 피드백 리포트(HTML)를 저장합니다.
사용자가 "AI 피드백" 또는 "구성원별 종합 리뷰"를 요청하면 이 가이드에 따라 동일한 UI로 생성합니다.

### 파일 네이밍
```
feedback/{팀명}_{분기}_{연도}_review.html
```

### 데이터 소스
- `rnr` 테이블 (1945): 직무기술/R&R
- `goals` 테이블 (1943) + `key_results` 테이블 (1944): OKR + KR 진척률
- `members` 테이블 (1942): 구성원 정보

### 평가 기준 (3개 축)

| 기준 | 비중 | 평가 내용 |
|---|:---:|---|
| 직무적합성 | 30% | R&R 대비 OKR 정합성, 본연의 역할 수행 |
| 역량 | 40% | OKR 설계 정량성, KR 달성 수준, 기술 난이도 대비 실행력, 업무 분량 적정성 |
| 근면성실도 | 30% | **실제 진척률 수치**, 업데이트 빈도, 목표 대비 착수 비율 |

### 종합 점수
```
종합 = (직무적합성 × 0.3) + (역량 × 0.4) + (근면성실도 × 0.3)
```
10점 만점, 0.1점 단위

### 중요 규칙
- **진척률 데이터를 반드시 최신으로 조회**한 후 평가 (과거 캐시 사용 금지)
- 진척률이 실제로 업데이트되어 있으면 "미착수"로 판단하지 않음
- 다수 KR이 0%여도 나머지에서 높은 달성률을 보이면 "전략적 집중"으로 인정
- OKR 수가 많아도 전체적으로 착수가 확인되면 근면성실도 감점하지 않음
- 감정 배제, 객관적 수치 근거만으로 평가

### 업무량 적정성 판단 (M/M · M/D 기반)
- **분기별 평가 시 3개월(약 60 M/D) 기준으로 목표 대비 실제 업무 투입량을 검증**
- 마케팅·콘텐츠 직군은 특히 엄격하게 적용:
  - 인스타 콘텐츠 발행 주 2회 = 월 8건 × 건당 0.5일 = 월 4 M/D → 분기 12 M/D
  - CRM 메시지(앱푸시/알림톡) 발송 = 월 4~8건 × 건당 0.25일 = 분기 3~6 M/D
  - 인플루언서 시딩 관리 = 월 5~10건 × 건당 0.5일 = 분기 7~15 M/D
  - 퍼포먼스 광고 운영(매체 세팅·리포팅) = 주 5일 상시 → 분기 60 M/D (전업)
  - 브랜드 영업(컨택·미팅·후속) = 건당 1~2일 × 월 5~10건
- **목표가 위 기준 대비 낮게 설정되었거나, 예상 투입 시간 합산이 분기 가용 시간(60 M/D)에 크게 못 미치면 "목표 수준이 낮음"으로 감점**
- 반복 업무(상시 운영)만으로 OKR을 채우고 도전적 목표가 없는 경우도 감점
- 개발 직군은 프로젝트 단위 M/M 산정이 명확하므로 동일 기준 적용 (1 M/M = 20 M/D)

### HTML 구조
- `max-width: 900px`, 배경 `#f8fafc`, 폰트 Pretendard
- 구성원별 카드: 종합점수 뱃지 + 3축 점수 + 서술 평가 + 강점/개선 태그
- 하단 요약 테이블: 전체 구성원 점수 비교

### 필수 규칙: 피드백 진행 시 파일 생성
- **피드백 진행을 요청하면 반드시 파일을 생성한다**
- AI 피드백 리포트 → `feedback_ai/` 폴더에 저장
- 일반 피드백 (팀장/본부장 작성) → `feedback_okr/` 폴더에 저장
- 구두 요약만으로 끝내지 않고, 항상 열람 가능한 HTML 리포트를 산출물로 남긴다
- 분기별 피드백 히스토리가 파일로 축적되어 과거 대비 성장 추적에 활용한다

### 파일 네이밍 규칙
- 형식: `YYMMDD_{팀명}_{연도}_{분기}_report[_ai][_shared].html`
- AI 피드백: `260706_DX_2026_Q2_report_ai.html` / `260706_DX_2026_Q2_report_ai_shared.html`
- 일반 피드백: `260706_DX_2026_Q2_report.html`
- YYMMDD = 생성일 (현재 연월일)
- `_ai` = AI 리포트인 경우에만 붙임
- `_shared` = 점수 없는 구성원 공유용 버전

### 디자인 가이드 참조
- 피드백 리포트, 평가표 등 문서의 디자인 양식을 수정하거나 새로 만들 때는 반드시 `docs/DESIGN_REPORT.md`를 참조한다
- 컬러, 폰트, 레이아웃, 표 스타일, 인쇄 규칙 등 모든 시각 요소는 해당 문서의 기준을 따른다
- 생성되는 HTML 리포트에는 항상 우상단에 "PDF 내려받기" 버튼을 고정 배치하며, `window.print()`로 동작한다 (인쇄 시 버튼은 숨김 처리)
- 각 `.page` div는 `width: 210mm; height: 297mm; overflow: hidden;`으로 고정하여 1페이지 = 1장이 되도록 한다
- `@page { size: 210mm 297mm; margin: 0; }` 적용으로 브라우저 머릿말/꼬릿말/추가 여백을 제거한다
- PDF 내려받기 시 인쇄 설정에서 여백 "없음", "머리글 및 바닥글" 해제를 안내한다

### 문서 타이틀 양식
- 타이틀은 `{연도}년 {분기} - {본부명} {팀명} 구성원별 AI 피드백 리포트` 형식을 따른다
- 예시: `2026년 2분기 - 운영본부 DX팀 구성원별 AI 피드백 리포트`
- 타이틀 바로 아래에 다음 안내 문구를 삽입한다:
  > 구성원들이 제출한 OKR, JD/R&R, 중간 체크인 데이터를 토대로 AI 모델(Claude)이 자동 생성한 피드백 리포트입니다. 주간업무내역 및 중간 체크인/코멘트 내용이 상세할수록 더 정확하고 올바른 결과물이 산출됩니다.

### 구성원 공유용 (점수 없는 버전) 생성 규칙
- 점수 없는 버전을 요청하면 `{팀명}_{분기}_{연도}_review_shared.html`로 별도 생성한다
- 종합 점수, 개별 축 점수(직무적합성/역량/근면성실도), score-badge, scores 영역을 모두 제거한다
- 요약 테이블(점수 비교표)도 제거한다
- 서술 평가는 유지하되, 톤을 "평가"에서 "피드백 + 3분기 집중 필요 항목" 형태로 전환한다
- 하단 안내 문구를 "구성원 공유용" 톤으로 변경한다

### 일반 피드백(OKR) 리포트 생성 규칙
- 일반 피드백(팀장/본부장 작성) 리포트는 `feedback_okr/` 폴더에 저장한다
- 각 Objective 아래에 해당 Key Results 리스트 및 진척률을 반드시 표시한다 (Objective → KR 리스트 → 피드백 코멘트 순서)
- KR 리스트와 피드백 코멘트 사이에 여백+가로선으로 시각적 분리를 확보한다 (margin-top: 8px, padding-top: 10px)
- 피드백 코멘트(feedback 필드)는 원문 그대로 반영하며, 가공·요약·축약하지 않는다
- KR 리스트 형식: `KR1. [KR텍스트] — [진척률]%`
- 콘텐츠가 1페이지를 초과하는 경우 수동 분할하지 않고, 인쇄 시 자동 페이지 분할되도록 한다 (height: auto, page-break-inside: avoid on fb-item)
- 본부장 피드백이 추가되면 동일 리포트에 병합 생성할 수 있음을 고려한다

### 구성원 정렬 규칙
- **직급순으로 정렬한다** (대표 → 본부장 → 팀장 → 멤버 순)
- 동일 직급 내에서는 종합 점수 높은 순으로 정렬한다

### 평가 핵심 원칙
- 단순 "목표 대비 달성률"만으로 점수를 산정하지 않는다
- **3개월 기간 내 실제 수행한 업무량(M/D 환산)**, **성취도(완료 품질 및 난이도)**, **실제 비즈니스 임팩트(매출 기여, 비용 절감, 프로세스 혁신 등)**를 종합적으로 판단한다
- 특히 마케팅·콘텐츠 직군은 목표 달성률이 높더라도 업무 투입량 자체가 적거나, 비즈니스 임팩트가 제한적이면 감점한다
- 반복 운영 업무만으로 KR을 채운 경우와 도전적 목표를 설정하고 실행한 경우를 구분하여 평가한다

### AI 피드백 서술 평가 작성 규칙
- **핵심 성과** 섹션: 완료된 KR을 단순 나열하지 않고, 각 성과가 왜 의미 있는지(비즈니스 임팩트, 기술 난이도, 조직 기여)를 1~2문장씩 설명한다
- **미착수/저성과** 섹션: 0% 또는 저조한 KR에 대해 단순 "미착수"로 끝내지 않고, 왜 미착수인지 추정 원인(리소스 부족, 우선순위 판단, 체크인 부재 등)을 명시한다
- **종합 판단** 섹션: 최소 5~8줄 이상으로 작성하며, 아래 내용을 모두 포함한다:
  - 분기 전체 업무량(M/D) 대비 실제 투입량 산정 및 잔여 시간 분석
  - 달성한 성과의 비즈니스 임팩트 종합
  - 미착수 항목에 대한 원인 분석 (체크인 부재, 우선순위, 외부 요인 등)
  - R&R 대비 본 분기 OKR의 정합성 평가
  - 반복 운영 업무 vs 도전적 업무의 비율 판단
  - 3분기 방향성 제언 (구체적)
- 코멘트는 감정을 배제하되, 차갑고 명확한 톤으로 작성한다
- 중간 체크인/코멘트가 없었던 OKR은 해당 사실을 반드시 언급한다
